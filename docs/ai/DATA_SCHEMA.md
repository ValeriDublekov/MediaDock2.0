# Data Schema

Compact map of the PostgreSQL persistence model in `server/`. This is an orientation page, not a field-by-field schema dump: entity files define properties, while [persistence configurations](../../server/src/MediaDock.Infrastructure/Persistence/Configurations/) and [migrations](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/) define the database schema. For ownership and rollout cautions see [Data contracts](DATA_CONTRACTS.md); for runtime persistence behavior see [Data behavior](DATA_BEHAVIOR.md).

## Important Database Invariants

- Most entity tables use generated `bigint` IDs. Exceptions include `imdb_titles` keyed by normalized IMDb ID, `omdb_daily_usage` keyed by UTC date, owner-scoped composite keys for favorites, ignored movies, and ratings, and the scheduler singleton key.
- `imdb_titles` is the sole provider-metadata owner. `oscar_movies`, `golden_globe_titles`, and `torrent_movies` may reference it; these source-owned tables keep source identity and optional IMDb links, not provider-field copies. `metadata_cache` is temporary resolver state, not canonical data.
- `imdb_titles.normalized_vote_weight` is global per canonical IMDb title and defaults to `0.0`; it is not personal data. `general_recommendation_settings.id = 1` owns `median_period_years`, `bayesian_default_c`, `bayesian_m_ratio`, the four source-level award-point defaults, `requires_vote_recalculation`, and last-success metadata. Recommendation coefficients are request values, not stored settings.
- Oscar nominations retain imported facts and can link to `oscar_movies` without requiring a catalog or torrent record. Golden Globes titles are unique by `(title, year, nominee_type)` and preserve both movies and series; nominations retain award, winner, and import facts.
- Golden Globes award `name` remains the raw display value; `category_key` stores the resolved key from the source-qualified alias dictionary. Unmapped names use `award_other`. Oscar `CanonicalCategory` remains the canonical Oscar key.
- `recommendation_award_weights` is unique by `(award_source, category_key)`, constrains points to nonnegative values, and uses `is_override` to distinguish custom category points from source-level defaults.
- A nonempty `torrent_movies.imdb_id` is unique. IMDb identity can merge known matches; title/year/type alone is insufficient to merge records when the IMDb ID is missing or conflicts. `torrent_releases` is unique by normalized `torrent_url` and by `(source_id, source_item_key)`; the latter pair is an index, not an immutable entity key, so the latest profile observation can update it.
- `favorite_movies` is keyed by `(user_id, imdb_id)` and references the shared `imdb_titles` table for movies and series. Oscar and catalog origins accept enriched movies; recommendation origin also accepts enriched series. Recommendation adds set `ToWatch` without setting `ToDownload`; `ToDownload` is movie-only and does not require a torrent release. Personal ratings remain separately owner-scoped by IMDb ID; rows present when the migration runs and newly imported rows default to `is_manually_added = false`.
- `user_ignored_movies` is keyed by `(user_id, imdb_id)` and has required restrictive foreign keys to `users` and `imdb_titles`. An ignored row cannot exist without its canonical IMDb title; the API accepts only movie records and scopes reads and deletes to the active owner.
- `SourceOwnedMovieIdentity` creates the active source-owned tables and does not copy legacy provider fallback fields into `torrent_movies`. The final `RemoveLegacyTitleIdentity` migration drops `titles`, `occurrences`, `oscar_films`, `golden_globe_groups`, `legacy_favorite_movies`, and the old nomination link columns after reporting remaining fallback/favorite counts. Its `Down` cannot restore dropped rows; see [Data contracts](DATA_CONTRACTS.md) for rollout cautions.
- `DeduplicateTorrentUrls` normalizes Rutracker topic links and retains one release per URL, choosing greatest `last_seen_at` and then greatest ID. It removes item states for discarded releases and catalog rows left without releases, while retaining parse logs and source configuration. Its `Down` cannot restore deleted rows; use a validated backup for recovery.
- Foreign keys are restrictive except job events, which cascade with their job. OIDC issuer/subject pairs are unique; partial unique indexes also enforce one pending registration per user and prevent duplicate scheduled or active jobs.
- Database checks enforce supported type/status values, job lifecycle and ownership shape, rating bounds, user role/status combinations, and valid timestamp/count ranges. All nine `scan_runs` counters are constrained to nonnegative values. Both settings rows are constrained to `id = 1`; legacy Oscar-specific setting columns remain on `settings` but are ignored.
- The schema has no optimistic concurrency token. For exact constraint names, column types, and index definitions, use the linked entity configurations and migrations.
