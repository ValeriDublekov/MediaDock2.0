# Data Schema

Canonical PostgreSQL entity, key, index, relationship, and check-constraint reference for `server/`. `MediaDockDbContext` exposes 23 sets and applies entity configurations from the Infrastructure assembly. The [persistence configurations](../../server/src/MediaDock.Infrastructure/Persistence/Configurations/) and [migrations](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/) are authoritative. For ownership and rollout cautions start at [Data contracts](DATA_CONTRACTS.md); for runtime persistence behavior see [Data behavior](DATA_BEHAVIOR.md).

Provider email and identity are not duplicated here. |

`MinMovieRating`, `MinSeriesRating`, and `MinImdbVotes` are persisted and returned by the settings API, but are not used by RSS matching or as catalog-filter defaults. They are compatibility fields; the ownership migration does not convert them into personal preferences or change their meaning.

`imdb_titles` is the canonical shared store for OMDb metadata whenever an IMDb ID is known. Nullable IMDb references on `titles`, `oscar_films`, and `golden_globe_nominations` point to this row; `personal_ratings` requires it. `titles` retains duplicated metadata fields for title-local fallback when there is no IMDb ID, along with local identity and torrent-observation timestamps. `metadata_cache` is a TTL resolver cache, not the canonical metadata store. Migrations only copy database metadata and never call OMDb.

IMDb IDs are trimmed and lowercased at CSV, import, and OMDb boundaries; blank title/award IDs become `NULL`. The `imdb_titles.imdb_id` primary key guarantees one shared row per normalized IMDb ID. The additive [`AddSharedImdbTitles`](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/20261016160138_AddSharedImdbTitles.cs) migration creates stubs from IDs in titles, ratings, Oscar films, and Golden Globes nominations; copies metadata from the newest ID-backed title row; normalizes existing references; keeps one title-level IMDb link for duplicate title IDs; deduplicates same-owner rating IDs by latest `UpdatedAt`; and then adds restrictive FKs. Metadata on title rows without an IMDb ID stays title-local and is not removed. The migration makes no provider requests. The `ux_titles_imdb_id` partial unique index permits multiple missing IDs but rejects duplicates. The title fallback index is deliberately non-unique: `ix_titles_normalized_title_year_media_type` allows different films with the same normalized title, year, and media type. Application fallback matching links an existing title only when its IMDb ID is absent or compatible with the incoming ID; it never merges two different non-null IDs.

`settings` is a singleton row with `CHECK (id = 1)`. The API-hosted dispatcher reads only key `1`; first creation uses that explicit key and retries a concurrent primary-key winner. There is no lowest-ID convention.

Foreign keys include `occurrences.title_id -> titles.id`, `occurrences.source_id -> sources.id`, nullable `parse_logs.source_id -> sources.id`, nullable `parse_logs.scan_run_id -> scan_runs.id`, nullable `background_jobs.scan_run_id -> scan_runs.id`, nullable `background_jobs.owner_user_id -> users.id`, `background_job_events.job_id -> background_jobs.id`, nullable `titles.imdb_id -> imdb_titles.imdb_id`, `favorite_movies.user_id -> users.id`, `favorite_movies.title_id -> titles.id`, `personal_ratings.user_id -> users.id`, required `personal_ratings.imdb_id -> imdb_titles.imdb_id`, nullable `oscar_films.imdb_id -> imdb_titles.imdb_id`, nullable `golden_globe_nominations.imdb_id -> imdb_titles.imdb_id`, `oscar_films.title_id -> titles.id`, `oscar_nominations.oscar_film_id -> oscar_films.id`, `golden_globe_nominations.award_id -> golden_globe_awards.id`, `external_identities.user_id -> users.id`, and `registration_requests.user_id -> users.id`. They use `RESTRICT` except job events, which cascade when a job is deleted.

Other non-unique indexes include `ix_rss_item_states_expires_at`, `ix_titles_normalized_title_year_media_type`, `ix_occurrences_title_id_last_seen_at`, `ix_scan_runs_started_at`, `ix_parse_logs_processed_at`, `IX_parse_logs_source_id`, `ix_background_jobs_status_enqueued_at`, `ix_background_job_events_job_id_id`, `ix_metadata_cache_expires_at`, `IX_favorite_movies_title_id`, `IX_personal_ratings_imdb_id`, `IX_oscar_films_imdb_id`, `IX_golden_globe_nominations_imdb_id`, `ix_oscar_films_film_year`, `ix_oscar_nominations_category_ceremony`, `ix_golden_globe_nominations_year_award`, `ix_oscar_enrichment_runs_started_at`, `ix_external_identities_user_id`, and `ix_registration_requests_user_id_requested_at`.

## Check Constraints

- `ck_sources_feed_type` restricts `sources.feed_type` to `movie`, `series_complete`, or `series_ongoing`; both series modes are treated as OMDb `series` and source years are season/episode years, not show premiere years.
- `ck_rss_item_states_disposition` restricts item state to `resolved` or `terminal`; `ck_rss_item_states_expiry` requires terminal decisions to have an expiry and permits temporary expiry on adopted legacy resolved entries.
- `ck_titles_media_type` restricts `titles.media_type` to `movie`, `series`, `documentary`, or `short`; `ck_titles_source_type` restricts nullable `source_type` to `movie` or `series`; `ck_titles_content_kind` restricts nullable `content_kind` to `standard`, `documentary`, or `short`.
- `ck_imdb_titles_imdb_id_normalized` requires a nonblank lowercased, trimmed IMDb ID; `ck_imdb_titles_metadata_status` restricts status to `pending`, `enriched`, `not_found`, or `temporary_error`; `ck_imdb_titles_enrichment_attempt_count` requires a non-negative attempt count.
- `ck_titles_seen_range` requires `titles.first_seen_at` and `titles.last_seen_at` to be both null or both set with `first_seen_at <= last_seen_at`; these fields represent torrent observations, not Oscar import or metadata enrichment. `ck_occurrences_seen_range` requires `occurrences.first_seen_at <= occurrences.last_seen_at`.
- `ck_scan_runs_status` restricts `scan_runs.status` to `running`, `succeeded`, `partial`, or `failed`; `ck_scan_runs_trigger` restricts `trigger` to `schedule`, `manual`, or `local`.
- `ck_scan_runs_finish_time` requires `running` rows to have a null `finished_at` and every completed status to have a non-null value.
- `ck_background_jobs_type`, `ck_background_jobs_trigger`, and `ck_background_jobs_status` restrict job types, triggers, and lifecycle statuses; `ck_background_jobs_type_trigger` permits scheduled RSS only and manual Oscar, Golden Globes, and IMDb-title enrichment jobs, including `golden_globe_manual_refresh`. `ck_background_jobs_owner_user_id` requires an owner only for `imdb_title_enrichment`.
- `ck_background_jobs_lifecycle` enforces queued/running/terminal timestamp shape. `ck_background_jobs_input_type` requires queued/running Oscar and Golden Globes imports to retain bytes and permits cleanup after terminal state; RSS, enrichment, and targeted manual refresh jobs never store upload bytes.
- `ck_oscar_films_enrichment_status` restricts the enrichment status to `pending`, `enriched`, `not_found`, or `temporary_error`; `ck_oscar_films_enrichment_attempt_count` requires a non-negative attempt count.
- `ck_golden_globe_nominations_enrichment_status` restricts Golden Globes status to `pending`, `enriched`, `problem`, `not_found`, or `temporary_error`; `ck_golden_globe_nominations_enrichment_attempt_count` requires a non-negative attempt count; `ck_golden_globe_nominations_nominee_type` restricts nominee type to `movie` or `series`.
- `ck_oscar_enrichment_runs_status` restricts Oscar run status to `running`, `succeeded`, `partial`, `quota_stopped`, `failed`, or `cancelled`; `ck_oscar_enrichment_runs_trigger` allows `manual` and `schedule`; `ck_oscar_enrichment_runs_counts` requires non-negative progress counters.
- `ck_oscar_enrichment_runs_finish_time` requires `running` rows to have a null `finished_at` and every completed status to have a non-null value.
- `ck_settings_singleton_id` restricts `settings.id` to `1`.
- `ck_settings_min_movie_rating` and `ck_settings_min_series_rating` restrict ratings to 0 through 10; `ck_settings_min_imdb_votes` restricts votes to 0 through 1,000,000,000.
- `ck_settings_omdb_daily_request_limit` requires a non-negative shared limit. Legacy `ck_settings_oscar_max_films_per_run` and `ck_settings_oscar_max_requests_per_day` constraints and columns remain for compatibility but are ignored by runtime code.
- `ck_personal_ratings_rating` restricts personal ratings to the inclusive range 1 through 10.
- `ck_favorite_movies_origin` requires at least one of `added_from_oscar` or `added_from_catalog` to be true.
- `ck_users_normalized_email` requires a non-empty lowercase trimmed email; `ck_users_given_name` and `ck_users_family_name` require nonblank separate profile names; `ck_users_status`, `ck_users_role`, and `ck_users_status_role` constrain lifecycle and role combinations.
- `ck_external_identities_issuer_subject` requires a nonblank issuer and subject. `ck_registration_requests_status` restricts request state; `ck_registration_requests_decision` requires a decision timestamp and operator identifier for approved/rejected requests and forbids them while pending.
- `ck_parse_logs_retry_state` restricts `parse_logs.retry_state` to `retryable`, `terminal`, or `resolved`; `ck_parse_logs_attempt_count` requires `attempt_count >= 0`.
- `ck_metadata_cache_status` restricts status to `found` or `confirmed_not_found`; `ck_metadata_cache_expiry` requires `expires_at > fetched_at`.
- `ck_omdb_daily_usage_counts` requires non-negative counts and `oscar_requests <= total_requests`.

The schema does not define an optimistic concurrency token. The unique IMDb key is database-enforced, while title/year matching remains a guarded application fallback and is intentionally non-unique.
