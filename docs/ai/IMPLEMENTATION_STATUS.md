# Implementation Status

This matrix describes the code and configuration in this repository. `Implemented` means the capability exists here; it does not claim a production deployment or a passing test run. `Not implemented` and `MVP limitation` are not delivery commitments.

The API-hosted ingestion architecture is implemented in this source tree. The
production host recorded in the handoff documents still runs the prior release;
the background-job migrations and legacy-unit cutover have not been deployed.

## MVP Matrix

| Area | Status | Shipped scope and boundary |
| --- | --- | --- |
| Web app and local runtime | Implemented | The React client is bundled into and served by the production API image; Compose provides the API and PostgreSQL, with the host port bound to loopback ([Compose](../../compose.yaml), [local runbook](../../README.md)). |
| Catalog | Implemented | Search, supported filters, pagination, title details, and occurrence history are available in the UI and API ([catalog view](../../web/src/features/catalog/CatalogView.tsx), [API contracts](API_CONTRACTS.md)). |
| Sources and matching settings | Implemented | The backend exposes immutable `movie`, `series_complete`, and `series_ongoing` profiles; configuration only adds, replaces, or removes HTTPS feed URLs within a profile. Profile IDs, not request-body fields or user labels, select parser and metadata behavior. The API migration preserves URLs, normalizes labels, and maps legacy `series` to `series_ongoing`. Matching thresholds/exclusions remain editable ([sources view](../../web/src/features/sources/SourceSettingsView.tsx), [API contracts](API_CONTRACTS.md)). |
| Provider settings | Implemented | The Configuration screen saves the OMDb key and shared/Oscar request limits in PostgreSQL. The API returns only a configured flag, not the key; the API job scope loads settings at execution time. The key is plaintext in the database and appears in SQL backups, so protect backups and keep the unauthenticated API on a trusted LAN ([settings view](../../web/src/features/sources/SourceSettingsView.tsx), [provider API](../../server/src/MediaDock.Api/Sources/SourceSettingsEndpoints.cs)). |
| Personal IMDb ratings import | Implemented | Configuration accepts one JSON export at a time, validates the complete file, and additively merges normalized IMDb IDs. Re-imports insert new ratings, update changed values, preserve unchanged values, and never delete ratings omitted from a file. This is shared local data; keep the unauthenticated API on the trusted network ([settings view](../../web/src/features/sources/SourceSettingsView.tsx), [import endpoint](../../server/src/MediaDock.Api/PersonalRatings/PersonalRatingsEndpoints.cs), [data contract](DATA_CONTRACTS.md)). |
| RSS ingestion and metadata | Implemented | Manual and scheduled scans enter a PostgreSQL queue and run through one API-hosted dispatcher. Sources select movies, complete seasons, or ongoing episodes; both series modes query OMDb as series and do not compare season years with the show's premiere range. Fingerprinted RSS item state skips unchanged resolved entries before metadata lookup and retries terminal decisions after two days. Scan history separates known skips from total entries and actual OMDb HTTP attempts. Oscar enrichment is queued separately ([dispatcher](../../server/src/MediaDock.Api/BackgroundJobs/BackgroundJobDispatcher.cs), [ingestion flow](../../server/src/MediaDock.Application/Ingestion/RssIngestionService.cs), [data contracts](DATA_CONTRACTS.md)). The feed host and parser scope are not a general-purpose RSS provider interface. |
| Oscar CSV import | Implemented, manual | Configuration uploads bounded CSV/TSV bytes into a durable job; the API executor imports films and nominations after the configured year from Best Picture, Directing, Original/Adapted Screenplay, and Cinematography. It preserves CSV fields and existing OMDb metadata, is idempotent, and does not call OMDb or create torrent occurrences ([importer](../../server/src/MediaDock.Infrastructure/OscarAwards/OscarDatasetImporter.cs), [runbook](../../README.md)). |
| Oscar OMDb enrichment | Implemented, manual | Configuration can queue Oscar metadata enrichment independently of RSS parsing. The API job handler processes due candidates newest-first using the UI-configured per-run film cap and Oscar daily request cap. Confirmed not-found results are terminal; transient errors are deferred; provider or shared-budget exhaustion stops the batch without losing unprocessed candidates. Every HTTP attempt reserves from the shared PostgreSQL UTC-day budget. A separate `oscar_enrichment_runs` table records lifecycle, progress, actual HTTP attempts, and safe error codes without changing RSS history semantics ([use case](../../server/src/MediaDock.Application/OscarAwards/OscarEnrichmentService.cs), [run repository](../../server/src/MediaDock.Infrastructure/OscarAwards/PostgresOscarEnrichmentRunRepository.cs), [budget](../../server/src/MediaDock.Infrastructure/Metadata/PostgresOmdbRequestBudget.cs)). |
| Oscar catalog | Implemented | A read-only, paginated API and separate React screen filter Oscar films by title, film year, canonical category, nomination outcome, and OMDb status. Film details retain all selected-category nominations and shared title metadata even when OMDb enrichment is missing; the Oscar catalog does not depend on torrent occurrences ([view](../../web/src/features/oscar/OscarCatalogView.tsx), [API contracts](API_CONTRACTS.md)). |
| Golden Globes catalog, import, and enrichment | Implemented, manual | A separate paginated catalog groups nominations by title and ceremony year and filters by search, ceremony year, award, and winner/nominee result. Configuration accepts CSV/TSV imports after a selected year; imports are idempotent and do not create canonical catalog titles or torrent occurrences. Manual OMDb enrichment validates returned IMDb IDs and ceremony years, retries transient errors, and consumes the shared daily request budget; it has no separate run-audit table ([catalog view](../../web/src/features/golden-globes/GoldenGlobeCatalogView.tsx), [importer](../../server/src/MediaDock.Infrastructure/GoldenGlobes/GoldenGlobeDatasetImporter.cs), [enrichment service](../../server/src/MediaDock.Application/GoldenGlobes/GoldenGlobeEnrichmentService.cs), [API contracts](API_CONTRACTS.md)). |
| Operations history and health | Implemented | The UI restores/polls active jobs and displays safe events; scan history and parse logs remain available, including filtering by scan run. The API exposes process-liveness and database-connectivity endpoints ([history view](../../web/src/features/history/HistoryView.tsx), [job endpoints](../../server/src/MediaDock.Api/BackgroundJobs/BackgroundJobEndpoints.cs), [API contracts](API_CONTRACTS.md)). |
| Persistence and schema | Implemented | PostgreSQL job queue/events/scheduler state, metadata persistence, and additive EF Core migrations are present. Only the explicit one-shot migration service migrates; the normal API dispatcher does not start in migration mode ([data contracts](DATA_CONTRACTS.md), [API startup](../../server/src/MediaDock.Api/Program.cs)). |
| Host scheduling and backup procedure | Implemented | Scan scheduling runs inside the API at 07:00/18:00 `Europe/Sofia`; systemd units remain for host backup, deployment, and firewall only. Detailed commands remain in the [local runbook](../../README.md) and [systemd runbook](../../deploy/systemd/README.md). |

## MVP Limitations

| Area | Status | Limitation |
| --- | --- | --- |
| Authentication and authorization | Not implemented | All API routes, including source/settings writes, are unauthenticated. Keep the app on loopback; the repository does not provide a safe internet-facing deployment. See [security and operations](SECURITY_AND_OPERATIONS.md). |
| Feed/provider coverage | MVP limitation | The transport allows only `feed.rutracker.cc`, the ingestion parser is source-specific, and metadata lookup uses OMDb. Arbitrary feed hosts and additional metadata providers are not supported. |
| Deployment and recovery | MVP limitation | The supplied deployment is local Compose or a single host with systemd, not a multi-user or internet-facing service. The source architecture is ready, but the recorded production host still needs a backed-up migration and legacy Worker-unit cutover. Backup/restore is operator initiated; no alerting service is included. |

No item in the limitations table is implicitly planned. A capability should be labelled `Planned` only when an approved plan explicitly commits to it; until implemented and verified, it is not part of the shipped MVP.
