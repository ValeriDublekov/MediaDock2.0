# API: Identity and Personal Data

Canonical contracts for Google sign-in, account linking and administration, favorites, and personal IMDb ratings. Shared paging, errors, and access modes are in [API contracts](API_CONTRACTS.md); cross-layer flow is in [Architecture](ARCHITECTURE.md).

## Routes

| Method and route | Request | Success | Other documented outcomes |
| --- | --- | --- | --- |
| `GET /api/auth/google/login` | None | `302` to Google's OIDC authorization endpoint when explicitly enabled and requested from the configured callback origin | `503 ProblemDetails` when disabled or the request origin does not match the configured callback. |
| `GET /api/auth/session` | None | `200 CurrentSessionResponse`; returns `AccountState = "anonymous"` without a valid session, otherwise validated identity, any linked/matched user, and latest registration-request state when present; includes Google sign-in and authorization-enforcement state | `401 ProblemDetails` for an authenticated cookie with invalid Google identity claims; the body includes a safe `reasonCode`, and `X-MediaDock-TraceId` correlates the response with the server warning log. For `missing_or_ambiguous_email_verification`, that log also records claim count, safe shape, and whether multiple claim values agree, never the claim values themselves. Identical repeated `email_verified` values are accepted; missing, blank, or conflicting values are rejected. Does not authorize other API routes. |
| `GET /api/auth/antiforgery` | None | `200 AntiforgeryTokenResponse` and an anti-forgery cookie; send the token as `RequestVerificationToken` on state-changing auth routes | Response is non-cacheable. |
| `POST /api/auth/google/link` | Empty body plus `RequestVerificationToken` header and anti-forgery cookie | `204` after one-time linking to the account matching the validated verified email | `400` for missing/invalid anti-forgery token; `401` without a valid Google session; `409` for an unmatched, already-linked, or conflicting identity. Account and identity come from server-validated claims, not request data. |
| `POST /api/auth/registration-requests` | Empty body plus `RequestVerificationToken` header and anti-forgery cookie | `200 RegistrationRequestResponse`; atomically creates a pending user, provider identity, and request, or returns the existing request for an already-linked registration identity. The client presents an explicit registration screen for an unmatched identity and submits only after the user selects **Request registration**. | `400` for missing/invalid anti-forgery token or incomplete Google name claims; `401` without a valid verified Google session; `409` when the identity is linked to a non-registration account or its verified email conflicts with an existing account. Email, names, issuer, and subject come from validated server claims, not request data. Repeated requests for the same linked identity are idempotent. |
| `POST /api/auth/logout` | Empty body plus `RequestVerificationToken` header and anti-forgery cookie | `204`; clears the MediaDock session cookie only | `400` for missing/invalid anti-forgery token. Does not sign the user out of Google. |
| `GET /api/admin/users` | `state=all|requested|active|deactivated`, optional `search`, `page`, `pageSize` | `200 AdminUsersPageResponse`; requires an active administrator when enforcement is enabled, otherwise remains open; includes names, email, status, role, and request state | `400` for invalid filters; `401` anonymous or `403` non-admin/unknown/deactivated callers when enforcement is enabled. Keep the API within its configured loopback/trusted-network boundary while open mode is enabled. |
| `POST /api/admin/registration-requests/{requestId:long}/decision` | `{ "decision": "approve"|"reject" }` plus anti-forgery token | `204`; requires an active administrator when enforcement is enabled and remains open otherwise. Approval atomically activates the user with role `user`; rejection leaves the user pending. `DecidedBy` is the active administrator's email when available, otherwise `open-mode`. | `400` for invalid decision or anti-forgery token; `401` anonymous or `403` non-admin/unknown/deactivated callers when enforcement is enabled; `404` for an unknown request; `409` when it is no longer pending. |
| `PUT /api/admin/users/{userId:long}/status` | `{ "status": "active"|"deactivated" }` plus anti-forgery token | `204` for an active/deactivated user account; requires an active administrator when enforcement is enabled and remains open otherwise | `400` for invalid status or anti-forgery token; `401` anonymous or `403` non-admin/unknown/deactivated callers when enforcement is enabled; `404` for an unknown user; `409` for pending users or deactivation of the last active administrator. Mutations are serialized transactionally. |
| `GET /api/favorites` | `status=all|to_watch|to_download`, `page`, `pageSize` | `200 PageResponse<FavoriteMovieResponse>` for the current active user | `400` invalid query; `401` anonymous; `403` unknown or deactivated identity. The owner comes from the validated server session; client owner IDs are ignored. |
| `POST /api/favorites` | `titleId`, `from=oscar|catalog` | `200 FavoriteMovieResponse` for the current active user | `400` invalid body; `401` anonymous; `403` unknown or deactivated identity; `404` when the movie or verified source is missing. |
| `PATCH /api/favorites/{titleId:long}` | Optional `toWatch`, `toDownload` booleans (at least one) | `200 FavoriteMovieResponse` for the current active user | `400` invalid markers or unavailable torrent; `401` anonymous; `403` unknown or deactivated identity; `404` when the current user has no such favorite. |
| `DELETE /api/favorites/{titleId:long}` | Canonical title ID | `204`; removes only the current user's row and is idempotent | `401` anonymous; `403` unknown or deactivated identity. |
| `GET /api/personal-ratings` | `page`, `pageSize`, `sort=asc|desc` | `200 PageResponse<PersonalRatingResponse>` for the current active user; default sort is descending personal rating | `400` invalid query; `401` anonymous; `403` unknown or deactivated identity. The owner comes from the validated server session. |
| `POST /api/personal-ratings/enrichment` | Empty body plus `RequestVerificationToken` header and anti-forgery cookie | `202 PersonalRatingsEnrichmentAcceptedResponse` when work is queued or already active for the user; `204` when no owned rating has eligible metadata | `400` for missing/invalid anti-forgery token; `401` anonymous; `403` unknown or deactivated identity. Queued work is owner-scoped. |
| `GET /api/personal-ratings/enrichment/{jobId:long}` | Job ID | `200 BackgroundJobResponse` with status for an IMDb-title enrichment job owned by the current user | `401` anonymous; `403` unknown or deactivated identity; `404` when the job is not an IMDb-title enrichment job owned by the current user. It does not expose rating IDs or scores. |
| `POST /api/personal-ratings/import` | Multipart `File` (JSON array of `{ id, rating }`) plus `RequestVerificationToken` header and anti-forgery cookie | `200 PersonalRatingsImportResponse` for the current active user; merge and totals include only that user's rows | `400 ValidationProblemDetails` for an invalid file or missing/invalid anti-forgery token; `401` anonymous; `403` unknown or deactivated identity. Owner is resolved from the validated server session; client-supplied owner IDs are ignored. |

## Identity Configuration And Behavior

Google sign-in is controlled by `GOOGLE_AUTH_ENABLED` (default `false`), `GOOGLE_AUTH_CLIENT_ID`, `GOOGLE_AUTH_CLIENT_SECRET`, and `GOOGLE_AUTH_CALLBACK_URI` (default `http://localhost:8080/signin-oidc`). When enabled, the callback must be the exact configured `/signin-oidc` URI: HTTP is accepted only for `localhost:8080`; other callbacks require HTTPS and a hostname. The Google Web application client must register the exact callback. Sign-in accepts any Google account with a verified email; there is no domain allowlist.

The API validates the provider identity and resolves `(issuer, subject)`, active status, and role from PostgreSQL; role changes and deactivation take effect on the next request. Registration derives email and separate profile-name claims only from the validated Google identity and requires both names. Bootstrap is a host-only Compose operation; its operator must obtain identity values from an authenticated `GET /api/auth/session` response because the tool itself does not validate Google claims. Approval activates the requester with the `user` role; rejection records the decision and leaves the user pending.

Favorites and personal ratings always resolve the validated `(issuer, subject)` to an active internal user. All list/count/page/add/update/delete operations, enrichment selection and writes, import merges, and totals are scoped to that owner. No personal route accepts an owner claim; administrators see only their own personal data by default. Personal scores are distinct from shared IMDb metadata projected from `imdb_titles`; ratings remain visible while metadata is pending or not found, with IMDb ID as the title fallback. Favorites retain source validation, independent markers, pagination, and the shared torrent-summary projection. Open mode does not make these personal-data routes public.

Personal-rating JSON is parsed in memory and is not stored as a file. Rows with a valid IMDb ID but a missing/null rating are skipped and listed in the success response; other invalid entries reject the file before database changes. Repeated imports add new IMDb IDs and update changed ratings, leave unchanged rows untouched, and retain IDs absent from a later file.

## Request DTOs

| DTO | Fields and validation |
| --- | --- |
| `PersonalRatingsQuery` | `Page` and `PageSize` use the common limits; `Sort` is `asc` or `desc` and defaults to `desc`. Ratings sort by personal score with normalized IMDb ID ascending as a deterministic tie-breaker. |
| `PersonalRatingsImportForm` | Required `.json` file, max 5 MiB and 50,000 entries. Each entry has an IMDb title `id` and integer `rating` (1..10). Valid IDs with a missing/null rating are skipped and listed in the success response; other invalid entries reject the file before database changes. |

## Response DTOs

Nullable response fields are marked `?`; collection fields are lists/arrays.

| DTO | Fields |
| --- | --- |
| `CurrentSessionResponse` | `Authenticated`, `Identity?`, `User?`, `AccountState` (`anonymous`, `linked`, `link_confirmation_required`, `unmatched`, `account_conflict`), `SignInEnabled`, `AuthorizationEnforced`, `RegistrationRequest?` |
| `CurrentSessionIdentity` | Validated `Issuer`, `Subject`, `Email`, `GivenName?`, `FamilyName?`, `ProfileComplete`; provider tokens are never returned. |
| `CurrentSessionUser` | Stored `Email`, `GivenName`, `FamilyName`, `Status`, and current database `Role?`; role is not read from browser-supplied claims. |
| `CurrentSessionRegistrationRequest` | Latest request `Status`, `RequestedAt`, `DecidedAt?` for the identity's linked user, when present. |
| `RegistrationRequestResponse` | Request `Status`, `RequestedAt`, `DecidedAt?`; does not include provider tokens or client-supplied identity data. |
| `AdminUsersPageResponse` | `Items` (`AdminUserResponse[]`), `Page`, `PageSize`, `TotalCount`, `TotalPages` |
| `AdminUserResponse` | `Id`, `Email`, `GivenName`, `FamilyName`, `Status`, `Role?`, `CreatedAt`, `RegistrationRequest?` |
| `AdminRegistrationRequestResponse` | `Id`, `Status`, `RequestedAt`, `DecidedAt?` |
| `AntiforgeryTokenResponse` | `RequestToken` |
| `FavoriteMovieResponse` | `TitleId`, `Title`, `Year?`, `MediaType`, `ImdbRating?`, `PosterUrl?`, `ToWatch`, `ToDownload`, `AddedFromOscar`, `AddedFromCatalog`, `CreatedAt`, `UpdatedAt`, `OscarFilmCount`, `NominationCount`, `WinCount`, `OccurrenceCount`, `LastSeenAt?` |
| `PersonalRatingsImportResponse` | `RatingsInFile`, `Added`, `Updated`, `Unchanged`, `TotalRatings`, `ImportedAt`, `Errors` (`Id`, `Message`) |
| `PersonalRatingResponse` | `ImdbId`, personal `Rating`, metadata `Title` (falls back to IMDb ID), `Year?`, `MediaType?`, OMDb rating/votes/metascore, genres/countries, director/plot/poster/runtime/awards/box office, and `MetadataStatus` (`pending`, `enriched`, `not_found`, or `temporary_error`) |
| `PersonalRatingsEnrichmentAcceptedResponse` | `JobId`, `Status`; returned when an owner-scoped enrichment job is queued or already active |
