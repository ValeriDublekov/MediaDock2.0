# Persistence And Data Contracts

This page routes PostgreSQL persistence work in `server/`. Entity configurations and migrations define the schema; repositories define persistence behavior. The repository documents intended behavior, not the state of a deployed database. Verify production state on the host.

## Canonical Ownership

- [`imdb_titles`](DATA_SCHEMA.md) is the sole shared owner of provider metadata. `oscar_movies`, `golden_globe_titles`, and `torrent_movies` own their source identity and may reference a normalized IMDb ID; they do not copy provider metadata or require a match to be imported. Unmatched source records therefore have no provider metadata.
- Oscar source identity and enrichment belong to `oscar_movies`; `oscar_nominations` retains award facts independently of catalog occurrences. Golden Globes identity belongs to `golden_globe_titles`, grouped by `(title, year, nominee_type)` so both movies and series remain distinct; nominations retain award and import facts.
- RSS catalog identity belongs to `torrent_movies`. Each normalized torrent URL has one `torrent_releases` row globally; `(source_id, source_item_key)` remains unique but is mutable as the latest RSS profile observation changes. Known URLs reuse their existing `torrent_movies` association before title parsing or metadata lookup. New URLs still require normal metadata matching; title/year/type alone does not authorize a catalog merge when IMDb identity is missing or conflicting.
- `favorite_movies` is owner-scoped by `(user_id, imdb_id)`, so the same enriched IMDb movie from Oscar, Golden Globes, or the RSS catalog is one favorite per user. `personal_ratings` remains separately owner-scoped by normalized IMDb ID. Personal scores remain separate from shared metadata; `is_manually_added` identifies ratings created by the recommendation watched action, new imports are unmarked, and import updates preserve the existing marker.
- Recommendation vote weights are shared per canonical IMDb title. `general_recommendation_settings.id = 1` owns the median period, Bayesian settings, source-level award defaults, and freshness metadata; `recommendation_award_weights` stores explicit source/category overrides. The three recommendation coefficients are sent by each user request and are not persisted.
- The final `RemoveLegacyTitleIdentity` migration drops `titles`, `occurrences`, `oscar_films`, `golden_globe_groups`, and `legacy_favorite_movies` after source-owned data transfer. Until it runs, these are transitional tables, not active owners. Remaining provider fallback values and retained legacy favorites are discarded, never copied into `torrent_movies`.
- Each `sources` row represents one RSS URL. Disabled sources are retained because releases, parse logs, and item states refer to them.

## Migration And Rollout Cautions

- The generated [`InitialRelationalSchema`](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/20260930122500_InitialRelationalSchema.cs) baseline replaces the six earlier migrations. A database whose `__EFMigrationsHistory` records those earlier migrations requires an explicit per-environment reset before this baseline can be applied. Follow the [one-time baseline reset procedure](../../deploy/systemd/README.md#one-time-baseline-reset-per-environment); do not infer deployed state from repository source.
- [`AddSharedImdbTitles`](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/20261016160138_AddSharedImdbTitles.cs) normalizes and consolidates existing IMDb references and metadata without provider requests, and aborts if legacy personal ratings contain blank IMDb IDs. Its data-preservation effects are summarized in [Data schema](DATA_SCHEMA.md).
- [`EnforceTitleMetadataOwnership`](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/20261020122556_EnforceTitleMetadataOwnership.cs) backfills missing shared provider fields, keeps populated `imdb_titles` values when copies differ, clears provider details from linked `titles`, and enforces that ownership rule. IMDb-less title fallback remains until the final cleanup migration; it is not transferred to a source-owned table.
- [`EnforceOscarFilmTitleIdentity`](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/20261020125713_EnforceOscarFilmTitleIdentity.cs) adds a deferred database foreign key for non-null Oscar source IMDb IDs without rewriting rows. Deferral lets import/enrichment transactions update both linked rows atomically. Its preflight aborts if a source ID differs from the linked title; audit and resolve any such data in staging before deployment. Null source IDs remain allowed.
- [`NormalizeGoldenGlobeGroups`](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/20261020150000_NormalizeGoldenGlobeGroups.cs) moves title/year/type group identity and shared IMDb/enrichment state into one parent row while preserving nomination facts. Its preflight aborts when legacy rows in one group disagree on IMDb link or enrichment state; reconcile those rows in staging before deployment.
- [`SourceOwnedMovieIdentity`](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/20261021061711_SourceOwnedMovieIdentity.cs) creates `oscar_movies`, `golden_globe_titles`, `torrent_movies`, and `torrent_releases`, then transfers source and release facts. Its preflight reports non-transferable favorite and IMDb-less fallback-metadata counts. Favorites transfer only when the linked `imdb_titles` row is enriched; same-user rows for one IMDb ID merge their marker/origin values. Other legacy favorite rows are deleted from the rollback copy. Provider fallback values are not copied into `torrent_movies`; legacy tables remain only until the cleanup migration.
- [`AllowSourceOwnedNominationLinks`](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/20261021080502_AllowSourceOwnedNominationLinks.cs) permits source nominations without requiring their legacy parent link. Its down migration refuses rollback when those links are null.
- [`RemoveLegacyTitleIdentity`](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/20261021111712_RemoveLegacyTitleIdentity.cs) reports remaining provider fallback title and retained legacy favorite counts, then drops the five transitional tables and old nomination link columns. It does not copy fallback metadata to `torrent_movies`. Its generated `Down` can recreate schema only, not deleted rows; restore from a validated pre-migration backup instead.
- [`DeduplicateTorrentUrls`](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/20261021130541_DeduplicateTorrentUrls.cs) canonicalizes Rutracker topic URLs, retains the most recently seen release per URL (ID breaks ties), deletes older release rows and their item states, and deletes `torrent_movies` left without releases. It preserves parse logs and source configuration. `Down` removes the uniqueness rules but cannot restore deleted rows; validate counts in staging and take a backup before applying outside disposable databases.
- [`AddMovieRecommendationPersistence`](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/20261022122143_AddMovieRecommendationPersistence.cs) adds zero-default global vote weights, vote freshness settings, source-qualified award aliases, and award-point weights. It creates `settings.id = 1` with current API defaults when absent, marks it dirty when movie rows already exist, and preserves existing settings, IMDb IDs, and personal-rating ownership. [`MoveRecommendationSettingsToDedicatedTable`](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/20261022123655_MoveRecommendationSettingsToDedicatedTable.cs) transfers vote-normalization values to `general_recommendation_settings.id = 1`, seeding defaults if absent, then removes those columns from `settings`; `AppSetting.UpdatedAt` and the provider/matching values remain in `settings`. Its `Down` restores the vote settings before dropping the dedicated table.
- [`AddRecommendationVoteInvalidationTriggers`](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/20261022140000_AddRecommendationVoteInvalidationTriggers.cs) marks global vote weights dirty when a movie is inserted, its year/vote count/media type changes, or the median period changes. It does not alter ownership: the dirty flag and normalized weights remain global.
- [`AddBayesianRecommendationSettings`](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/20261023073045_AddBayesianRecommendationSettings.cs) adds the Bayesian and source-level award defaults plus an explicit category-override flag. It preserves customized category points and marks existing movie weights dirty because the popularity formula changed.
- [`AddManualPersonalRatingFlag`](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/20261023082306_AddManualPersonalRatingFlag.cs) adds non-null `personal_ratings.is_manually_added` with default `false`, preserving existing and imported rows as non-manual; the recommendation watched action sets it to `true`.
- [`AddUserOwnershipToFavoritesAndRatings`](../../server/src/MediaDock.Infrastructure/Persistence/Migrations/20261016071457_AddUserOwnershipToFavoritesAndRatings.cs) changes personal data to owner-scoped composite keys: it deletes legacy favorites/ratings when there are no users, assigns them to the only user when exactly one exists, and copies every legacy row to every user when multiple users exist. Its down migration refuses rollback with multiple users. Review these data effects and the identity migration tests before applying it to an existing database.
- Apply migrations only through the documented isolated/staging and deployment procedures. Routine tests use disposable databases and must never be pointed at production data.

For migration details, consult the migration files and [Data schema](DATA_SCHEMA.md). For operational deployment state and safety gates, use [operations](OPERATIONS.md) and the [local runbook](../../README.md).
