# API: Operations and Jobs

Task router for health/version, application configuration, deployment, operational history, ingestion, and background jobs. Shared paging, errors, and access modes are in [API contracts](API_CONTRACTS.md); cross-layer flows are in [Architecture](ARCHITECTURE.md).

## Client-visible and operator rules

- With access enforcement enabled, configuration, operational history, background jobs, and deployment require an active administrator. Open mode makes these routes unprotected; keep them within the configured loopback or trusted-network boundary. See [access modes](API_CONTRACTS.md#access-modes).
- Deployment control proxies only a fixed request set to the host service. Clients cannot supply commands, paths, or unit names, and the endpoints must remain within the trusted LAN boundary. Retrying a failed deployment gate never clears the separate deployment-failure marker.
- Provider settings never return the saved OMDb key. Usage and job projections expose bounded/safe operational data, not credentials or provider request URLs.
- Background work is asynchronous; clients follow the returned job identity to read status and events. Personal IMDb-title enrichment is owner-scoped, and global job status/events do not expose personal rating IDs or scores.
- `POST /api/background-jobs/imdb-title-import` accepts an administrator-only TSV upload in multipart field `File` and returns `202 Accepted`. The import job reports inserted, ignored, and unsupported-type row counts, then queues shared IMDb catalog enrichment when eligible rows remain; follow the import ID and, when present, the enrichment job ID through `GET /api/background-jobs/{id}`. The catalog worker uses the shared daily OMDb budget and the scheduler retries remaining eligible rows at its daily slots.
- RSS scans do not run award-catalog imports or enrichment as follow-up operations.
- `GET /api/parse-logs?ignored=true` returns ignored torrent-entry failures but excludes feed-level errors; omit `ignored` to include those diagnostics in the full parse log.
- `GET /api/parse-logs?unresolvedMoviesOnly=true` returns unresolved movie-feed entries, including retryable and terminal states while excluding resolved entries and feed-level errors.
- Parse-log IMDb matching is administrator-only. `POST /api/parse-logs/{id}/imdb-candidates?page=N` searches by the parsed film name (or reparses the raw torrent title), with pages 1-100; `POST /api/parse-logs/{id}/imdb-match` applies a confirmed result only when the log retains a source and usable torrent URL. Applying updates the selected log to resolved, appends a resolved `manual_retry` entry in the same scan scope, and disables further matching; rejecting candidates changes nothing.
- `DELETE /api/operation-history?olderThanDays=N` removes parse logs older than the UTC cutoff and completed scan summaries older than their start-time cutoff. The retention period must be 1-36,500 days. Active scans and their parse logs remain; retained parse logs and background jobs linked to deleted scan summaries are preserved with the scan link cleared. The response reports the cutoff and deleted scan/log counts.
- `GET /api/admin/movie-tables-dashboard` returns aggregate counts, type breakdowns, and enrichment states for canonical IMDb titles, Golden Globes, and Oscar tables.
