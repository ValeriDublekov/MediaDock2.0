# План: Импорт на Oscar CSV през уеб интерфейса

**Статус:** реализирано чрез API-hosted background jobs; историческата спецификация по-долу е superseded
**Последна редакция:** 2026-10-01

> Актуалният contract е в [server-hosted background ingestion plan](BACKGROUND_INGESTION_PLAN.md) и [API contracts](API_CONTRACTS.md). Импортът се изпраща към `POST /api/background-jobs/oscar-import`, връща `202`, пази ограничените bytes с queued job и ги изтрива при terminal state. Няма Worker CLI или API host-path режим; UI наблюдава job status/events.

## Цел и граници

Операторът избира локален Oscar CSV/TSV файл в уеб интерфейса и задава праг за година на филма, без достъп до файловата система на сървъра. Запазват се правилата за петте категории, идемпотентността, връзката с `titles` и липсата на OMDb заявки при импорт. Отделна CLI команда не остава.

Това е добавка към [плана за Oscar каталога](OSCAR_CATALOG_PLAN.md), а не нов importer или отделен източник на Oscar данни. Файлът не се съхранява трайно и не се добавя в Git. Източникът, датата/версията и SHA-256 на използвания dataset се записват от оператора извън Git съгласно действащия runbook; отчетът трябва да показва checksum, за да улесни това.

## Налична основа

- `OscarDatasetImporter.ImportAsync(path, yearAfter)` и `OscarCsvDatasetReader.Read(path, ...)` работят с локален файлов път и четат целия dataset преди транзакцията. Поддържат compact CSV и tab-separated `full_data.csv`; форматът и header-ите се проверяват от reader-а.
- Worker държи session-level PostgreSQL advisory lock по време на import или scan/enrichment. Заключването е в Worker проекта; API не го използва. API не трябва да стартира Worker или да заобикаля тази координация.
- Oscar API предоставя само четене, а Oscar екранът вече има каталог и състояния за зареждане/грешка. API няма authentication/authorization: всеки клиент, достигнал loopback или разрешената LAN мрежа, би могъл да задейства импорт.

## Предложено решение

### 1. Общ изпълнител и координация

- Изнася се същият advisory lock ключ и lease механизъм в общ за API и Worker компонент, без промяна на поведението на Worker. И двата пътя придобиват заключването преди импорт; при зает lock заявката отказва с `409 Conflict` и указание за повторен опит, вместо да чака неограничено. Това не блокира обикновените catalog reads.
- API регистрира съществуващия `OscarDatasetImporter` с отделен scoped `MediaDockDbContext`. CLI и уеб потокът споделят филтрите, транзакционния upsert и отчета; не се дублира CSV парсването. Проверява се, че не се извиква OMDb и че конфликтен импорт не започва транзакция.

### 2. HTTP договор и входна защита

- `POST /api/oscars/imports` приема `multipart/form-data`: един файл (`file`) и незадължителен `yearAfter` с default `1980` (само цели години в разумен диапазон, например `1800..2200`). При успех връща `200` с полетата на `OscarImportSummary` и SHA-256 на качения файл; нулев резултат от валиден файл се отчита като успешен импорт с нулеви включени записи.
- Валидация преди DB работа: точно един непразен файл, максимален размер с конфигуриран праг, напр. 20 MiB, без доверие на filename, extension или Content-Type за проверка на формата. Налагат се request/form/multipart лимити и лимит при копиране, така че голямо тяло да не се буферира без граница. Невалиден или повреден CSV, липсващи колони и невалидна година връщат `400 ValidationProblemDetails`; надвишен размер връща `413 ProblemDetails`; зает lock връща `409 ProblemDetails`. Неочаквана DB грешка остава сървърна грешка, без изтичане на съдържание от файла в response/log.
- Качването се копира в случаен временен файл в защитена директория на API хоста/контейнера и се хешира при копиране. Пътят е сървърно генериран, без части от клиентското име; файлът се изтрива във `finally` при успех, отказ, cancellation или грешка. Lock-ът се държи само за четенето/записа на импорта, не докато клиентът качва файла. Проверяват се и лимитите на reverse proxy, ако има такъв.
- Понеже API днес е без автентикация, качването е разрешено само в съществуващата доверена loopback/LAN граница. Преди включване за недоверени клиенти е нужна автентикация/разрешение за импорт; не се разширяват bind адресът и firewall allowlist-ът за тази функционалност. Дори в доверена мрежа лимитите и едновременният lock са задължителни.

### 3. Уеб поток

- В Oscar каталога се добавя компактна import секция/диалог с избор на локален `.csv`/`.tsv` файл, числово поле „След година“ (по подразбиране 1980) и бутон за импорт. Показват се избраният файл, размерът му и ясна индикация при изпращане; забранява се повторно изпращане докато заявката е активна.
- Клиентът изпраща `FormData` без ръчно зададен `Content-Type`, показва отчетените прочетени/пропуснати редове, създадени заглавия/филми и създадени/обновени номинации, плюс checksum. При `400`, `409`, `413`, загуба на мрежа или отменено изпращане показва конкретна грешка и запазва избора/годината за повторен опит. След успех обновява Oscar списъка и неговия брой, като не променя активните филтри; нулев резултат се обяснява чрез броячите за пропускане.
- Запазват се текущите модели за error/loading и достъпност: етикети на входовете, keyboard достъп, status съобщения за резултата и видим фокус. Импортът не стартира enrichment автоматично; той остава в съществуващия Worker цикъл и OMDb бюджет.

4. [ ] Интеграционни тестове с inline CSV/TSV и Testcontainers за успех, повторен import, невалиден файл, празен/прекалено голям файл, зает lock, cleanup и липса на occurrences/OMDb; web тестове за `FormData`, loading/errors и refresh след успех. Операторско приемане с конкретен файл, размер/време за обработка, SHA-256 и повторен импорт в разрешена среда; без автоматично пускане в продукция.

## Критерии за готовност

- Операторът импортира файл от браузъра без да го копира в контейнера; вижда смислен отчет и обновения Oscar каталог.
- CLI и UI дават същите резултати за един и същ файл/праг; повторно качване не дублира данни, не изтрива OMDb метаданни и не създава torrent occurrences.
- Невалиден/голям файл не оставя частични DB промени или временни файлове; паралелен Worker run или import не се припокрива с уеб импорта.
- API остава loopback-bound по подразбиране; преди LAN употреба е потвърдено, че достъпът е само от доверената allowlist, защото endpoint-ът няма удостоверяване.
